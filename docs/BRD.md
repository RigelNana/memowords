# MemoWords — Business Requirements Document (BRD)

## 1. 项目背景

### 1.1 问题陈述

当前市面上的词典工具存在以下痛点：

- **GoldenDict-ng**：功能强大但 UI 过时（Qt Widget），技术栈老化（C++/Qt），编译复杂，二次开发成本高
- **Anki**：背单词优秀，但词典查询能力弱，不支持 MDX 格式
- **欧路词典**：体验好但闭源付费，无法自定义扩展
- **在线词典**：依赖网络，无法利用用户本地海量 MDX 词典资源

需要一款 **将高性能词典查询与科学背单词融为一体** 的现代化开源桌面应用。

### 1.2 项目愿景

> 打造一款基于 Rust 的高性能、美观、开源的词典与背单词桌面应用，让语言学习者高效利用 MDX/MDD 词典资源，同时享受科学的间隔重复记忆体验。

## 5. 约束条件

### 5.1 技术约束

- 前端：React + TypeScript + TailwindCSS，Material UI 3 设计风格
- 后端：Tauri 2 + Rust，tokio 异步，sqlx + SQLite
- 词典解析：独立 `mdict` crate，不依赖 C/C++ FFI
- 所有依赖包使用最新稳定版本

### 5.2 架构约束

- 六边形架构 (Hexagonal / Ports & Adapters)
- DDD 领域驱动设计
- mdict 解析库作为独立 crate 与主应用分离
- 命名简洁清晰，代码风格统一

### 5.3 质量约束

- Smoke Test：每次构建自动运行
- 单元测试：每个功能模块覆盖，含边缘 case
- 集成测试：跨模块交互覆盖
- E2E 测试：核心用户场景覆盖
- 压力测试：大词典 (100K+ 词条) 场景

### 5.4 流程约束

- 使用 Git 版本控制
- 小功能直接提交到主分支
- 大功能开独立分支 (feature branch) 开发后合并

## 7. 风险评估

| 风险 | 可能性 | 影响 | 缓解措施 |
| --- | --- | --- | --- |
| MDX 格式变种导致解析失败 | 中 | 高 | 收集多种 MDX 词典做兼容性测试 |
| CSS 隔离不完善导致样式污染 | 中 | 中 | Shadow DOM 或 scoped CSS + 前缀隔离 |
| LZO 解压在 Rust 中无成熟库 | 低 | 高 | 调研 minilzo-rs 或自行绑定 |
| 大量词典并发加载导致 OOM | 低 | 高 | 延迟初始化 (deferred init) + 流式处理 |
| Tauri IPC 序列化大数据瓶颈 | 中 | 中 | 分块传输 + 流式 event |

## 8. 术语表

| 术语 | 定义 |
| --- | --- |
| MDX | MDict Dictionary Format — 词典数据文件 (.mdx) |
| MDD | MDict Resource Format — 词典资源文件 (.mdd)，存储图片/音频/CSS |
| FST | Finite State Transducer — 有限状态转换器，用于高效前缀/模糊搜索 |
| B-Tree | 平衡树索引结构，用于有序数据的高效查找 |
| SM-2 | SuperMemo 2 算法 — 经典间隔重复算法 |
| FSRS | Free Spaced Repetition Scheduler — 新一代间隔重复算法 |
| DDD | Domain-Driven Design — 领域驱动设计 |
| Hexagonal | 六边形架构 — Ports & Adapters 架构模式 |
